# 아키텍처 설계

## 아키텍처 스타일
본 시스템은 **모듈형 모놀리식(Modular Monolith)** 구조로 설계되었습니다.

- 초기 구현 및 이해 비용을 낮추고
- 명확한 모듈 경계를 통해
- 향후 서비스 분리가 가능하도록 설계합니다

---

## 주요 모듈

### Payment API
- 가맹점 요청 진입 지점
- 요청 검증 및 인증
- Command 전달 역할

### Payment Core
- 결제 도메인의 핵심 로직
- 상태 전이(State Transition) 관리
- 외부 결제 시스템 호출 오케스트레이션

### Acquirer Adapter
- VAN / 카드사 연동 추상화 계층
- 외부 시스템 변경이 도메인에 영향을 주지 않도록 격리

### Ledger / Event Store
- 결제 상태 변경 이력 저장
- 정산 및 감사의 기준 데이터 제공

### Operator Query
- 운영자/CS 조회 전용 읽기 모델
- 쓰기 로직과 명확히 분리

---

## 핵심 설계 원칙
- 도메인 로직은 외부 시스템에 의존하지 않는다
- 외부 장애는 항상 “예외 상황”으로 취급한다
- 상태 변경은 반드시 기록으로 남긴다
