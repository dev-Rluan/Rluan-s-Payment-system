# 개요 (Overview)

## 이 문서의 목적
본 문서는 **Rluan’s Payment System**의 설계 배경과  
전체적인 방향성을 설명하기 위한 문서입니다.

---

## 프로젝트 배경
결제 시스템은 단순히 “요청 → 승인”으로 끝나지 않습니다.  
실제 운영 환경에서는 다음과 같은 질문에 답할 수 있어야 합니다.

- 이 거래는 왜 실패했는가?
- 중복 요청은 어떻게 처리되었는가?
- 외부 시스템 장애 시 내부 상태는 어떻게 보장되는가?
- 이 데이터는 정산 기준으로 신뢰할 수 있는가?

이 프로젝트는 이러한 질문에 **설계 수준에서 답하는 것**을 목표로 합니다.

---

## 설계 원칙
- 도메인 중심 설계 (Domain-first)
- 명시적인 책임과 경계
- 상태 기반 사고(State-oriented Design)
- 변경 이력은 삭제하지 않는다 (Immutable Log)
