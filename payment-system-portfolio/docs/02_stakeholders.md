# 이해관계자 (Stakeholders)

## 주요 이해관계자

### 가맹점 (Merchant)
- 결제 승인/취소/조회 API를 호출하는 주체
- 관심사:
  - 빠르고 안정적인 응답
  - 중복 요청에 대한 안전한 처리
  - 명확한 실패 사유

### 최종 사용자 (End User)
- 실제 결제를 수행하는 사용자
- 시스템과 직접 통신하지는 않지만,
  결제 실패/지연에 가장 민감한 주체

### 운영자 / 고객센터
- 결제 장애, 민원 대응 담당
- 관심사:
  - 거래 검색
  - 상태 변경 이력 확인
  - “왜 실패했는지” 설명 가능성

### 정산 / 재무 담당
- 매출 및 정산 데이터 활용
- 관심사:
  - 원장 데이터의 신뢰성
  - 기간별 집계 가능 여부

### 외부 결제 시스템 (VAN / 카드사)
- 승인/취소를 실제로 처리하는 외부 시스템
- 장애 및 응답 지연 가능성을 항상 내포

---

## 설계 시 고려 사항
- 각 이해관계자의 관심사를 **하나의 책임으로 섞지 않는다**
- 운영자/정산 요구사항은 사후에 “끼워 넣지 않고”
  초기 설계에서부터 고려한다
