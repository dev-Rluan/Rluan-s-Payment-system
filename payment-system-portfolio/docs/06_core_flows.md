# 핵심 흐름 (Core Flows)

## 결제 승인 흐름(API)

1. 가맹점 결제 UI -> 가맹점 백엔드 결제요청 API 호출 → /payments/authorize (202 Accepted)
2. 결제 요청 데이터 검증
3. Payment 요청 데이터 저장 (PENDING)
4. 외부 결제 시스템 승인 요청 및 가맹점에게 202 응답
5. 가맹점이 Polling 또는 Webhook으로 최종 상태 확인
6. 결제 상태에 따라 UI 표시

---

## 결제 취소 흐름

1. 원거래 조회
2. 취소 가능 상태 검증
3. 외부 결제 시스템 취소 요청
4. 결과에 따라 상태 전이
5. 취소 이력 기록

---

## 조회 흐름
- 승인/취소 로직과 완전히 분리된 읽기 전용 흐름
- 운영자/가맹점 모두 동일한 원장 기준 조회
